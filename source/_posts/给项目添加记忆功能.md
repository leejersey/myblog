在 LangChain 中，给 Agent 加上记忆的核心概念叫做 **`RunnableWithMessageHistory`**。

这就好比在 JS 的 Redux 或 Vuex 中管理状态一样，我们需要一个地方存聊天记录（History），并在每次调用 AI 时，把之前的聊天记录作为 Context 塞进去。

###升级版：带记忆的 AI 助理我们将对 `main.py` 进行重构。为了方便演示，我们暂时把记忆存在**内存**里（重启服务会丢失），生产环境通常会换成 Redis。

####1. 更新依赖我们需要 LangChain 的社区包来管理聊天记录：

```bash
pip install langchain-community

```

####2. 代码重构 (`main.py`)我会重点标注出**新增和修改**的部分。

```python
import os
from dotenv import load_dotenv
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel, Field # Field 用于添加元数据
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain_core.output_parsers import StrOutputParser
# --- 新增：记忆管理模块 ---
from langchain_community.chat_message_histories import ChatMessageHistory
from langchain_core.chat_history import BaseChatMessageHistory
from langchain_core.runnables.history import RunnableWithMessageHistory

load_dotenv()

app = FastAPI(title="AI Agent with Memory")

# --- 1. 模拟数据库 (InMemory Store) ---
# 在 JS 里这就像 const store = {};
# 键是 session_id，值是聊天记录对象
store = {}

# 获取或创建 Session 的辅助函数
def get_session_history(session_id: str) -> BaseChatMessageHistory:
    if session_id not in store:
        store[session_id] = ChatMessageHistory()
    return store[session_id]

class ChatRequest(BaseModel):
    # session_id 就像用户 ID 或会话 ID
    session_id: str = Field(..., description="唯一的会话ID，用于区分不同用户")
    message: str
    
llm = ChatOpenAI(model="gpt-3.5-turbo", temperature=0.7)

# --- 2. 修改 Prompt 模板 ---
# MessagesPlaceholder 是关键，它为历史记录留出了位置
prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一个专业的AI技术顾问。请用简洁、专业的风格回答问题。"),
    # 这里的 "history" 是一个变量名，要和后面配置对应
    MessagesPlaceholder(variable_name="history"), 
    ("human", "{message}")
])

# --- 3. 构建基础链 ---
runnable = prompt | llm | StrOutputParser()

# --- 4. 包装链条，注入记忆能力 ---
# 这就像 React 的 Higher-Order Component (HOC)
with_message_history = RunnableWithMessageHistory(
    runnable,
    get_session_history,          # 如何获取历史记录的函数
    input_messages_key="message", # 用户输入对应的变量名
    history_messages_key="history" # 历史记录插入到 Prompt 的哪个位置
)

@app.post("/chat")
async def chat(req: ChatRequest):
    # 调用 invoke 时，除了传参，还要传 config
    # config 里的 session_id 会被传给 get_session_history 函数
    try:
        response = with_message_history.invoke(
            {"message": req.message},
            config={"configurable": {"session_id": req.session_id}}
        )
        return {"reply": response}
    except Exception as e:
        raise HTTPException(status_code=500, detail=str(e))

if __name__ == "__main__":
    import uvicorn
    uvicorn.run("main:app", host="0.0.0.0", port=8000, reload=True)

```

###如何测试记忆功能？这一步非常关键，因为我们需要验证它是否真的记住了之前的对话。

1. **启动服务**：`python main.py`
2. **打开 Swagger UI**：`http://127.0.0.1:8000/docs`

####第一轮对话：建立上下文发送请求 (Session ID: `user1`):

```json
{
  "session_id": "user1",
  "message": "我是 Jack，我是一名 Python 初学者。"
}

```

*AI 回复*：你好 Jack，很高兴认识你...

####第二轮对话：测试记忆发送请求 (**保持 Session ID: `user1**`):

```json
{
  "session_id": "user1",
  "message": "我刚才说我叫什么名字？"
}

```

*AI 回复*：你刚才说你叫 Jack。

####第三轮对话：测试隔离性 (换个用户)发送请求 (**Session ID: `user2**`):

```json
{
  "session_id": "user2",
  "message": "我叫什么？"
}

```

*AI 回复*：抱歉，我不知道你的名字... (因为它查的是 user2 的 store，那是空的)

###JS 开发者视角的复盘1. **State Management (状态管理)**：
这里的 `store` 字典就是最原始的状态管理。在生产环境中，Python 开发者通常使用 **Redis** 来持久化这个 `ChatMessageHistory`。LangChain 有现成的 `RedisChatMessageHistory` 类，替换掉 `InMemory` 版本只需要改两行代码。
2. **Dependency Injection (依赖注入)**：
`get_session_history` 函数被作为参数传递给了 `RunnableWithMessageHistory`。每当有请求进来，LangChain 会自动调用这个函数去“拉取”历史记录。这是一种典型的控制反转 (IoC)。
3. **Configurable Fields**:
注意 `config={"configurable": {"session_id": ...}}` 这种写法。这是 LangChain 特有的传参方式，专门用于传递那些**不属于 Prompt 内容**，但是用于**控制流程**的元数据（比如 Session ID、User ID、Tags 等）。

怎么样？这个带记忆的版本是不是更有“智能体”的感觉了？下一步如果想做复杂点，可以把这个 memory 换成 Redis，或者试着让它能够**上网搜索 (Tool Use)**。
